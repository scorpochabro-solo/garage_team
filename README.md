# ГАРАЖ · garage.team

Статический сайт автосервиса в Нижнем Новгороде. Актуальная редакция от **11.10.2026**:
ответы владельца и правки со скриншотов; при противоречии приоритет у скриншотов.
Ветка разработки — `photos`. Сборка: **102 страницы**, 21 направление и 90 страниц услуг.
Цены, магазин, каталоги деталей, доставка, корзина и скидка за регистрацию убраны.

## Запуск и проверка

```bash
python3 build.py                         # полная сборка; для изображений нужен Pillow
python3 build.py --reuse-images          # повторная сборка с сохранением готовых изображений
python3 -m http.server 5181 --bind 127.0.0.1 --directory dist
python3 seo/validate_content.py
python3 -m unittest discover -s tests
node --check dist/assets/js/site.js
```

Локальный адрес: http://127.0.0.1:5181/. `--reuse-images` проверяет даты исходников:
изменённые фото пересобираются, готовые неизменённые изображения сохраняются перед очисткой `dist`.

## Что требуется на сервере

Эта сборка статическая. GitHub Pages подходит для просмотра; сам по себе он не отправляет заявки в CRM.
Формам нужны серверные обработчики существующих маршрутов и справочника автомобилей.
Успех показывается только при корректном JSON с подтверждением создания заявки;
ответ HTML, пустой JSON и HTTP-ошибки не считаются отправленной заявкой.
К живой CRM во время этой редакции не подключались.

### Онлайн-гараж

Сейчас `/moya-mashina/` — рабочий локальный черновик: паспорт автомобиля, журнал работ,
пробег, напоминания, экспорт и импорт. На странице явно указано, что данные пока только в этом браузере.
Онлайн-вход отключён до подключения серверной части. SMS-доставка не подтверждена.

Разработчику CRM нужно предоставить API авторизации, список автомобилей текущего клиента,
историю именно выполненных работ, пробег, записи клиента и настройки следующего ТО.
После входа единственная машина открывается сразу; при нескольких клиент выбирает карточку машины.
Нельзя искать владельца только по введённому VIN или давать доступ по чужому `car_id`.
Сервисные ключи CRM остаются на сервере. Исходники CRM для интеграции не нужны.
Техническое ТЗ: `_plans/crm-online-garage-api-2026-10-09.md` (локальный документ, не входит в сборку).

### Источник погоды

По умолчанию браузер запрашивает `/api/weather` с параметрами Open-Meteo.
На сервере нужен прокси: коммерческий доступ или собственный совместимый источник,
серверное хранение ключа и общий кэш прогноза. Контракт ответа — формат Open-Meteo daily.
Маршрут прокси можно задать переменной сборки `GARAGE_WEATHER_ENDPOINT=/api/weather`.
Пока прокси недоступен, блок честно показывает общее правило и предлагает записаться,
без выдуманного прогноза. Кэш браузера — 2 часа.

Только для локального ознакомления и прототипирования:

```bash
GARAGE_WEATHER_PREVIEW=1 python3 build.py --reuse-images
```

Это явно включает прямой бесплатный источник. Для рабочего коммерческого сайта этот режим не использовать:
[условия Open-Meteo](https://open-meteo.com/en/pricing) разрешают бесплатный доступ для оценки и прототипирования,
а коммерческий hosted API требует подписки. Ключ в сборку никогда не помещать.

## Фото услуг (kie.ai, GPT Image 2.5)

Фото сгенерированы, это не снимки сервиса «Гараж». Поэтому на странице у фото стоит подпись «иллюстрация»
(`PHOTO_LABEL` в `build/services.py`), и подписывать их как «фото наших работ» нельзя. Реальные фото из боксов
кладутся в тот же `src/assets/img/photo/<slug>.jpg`, тогда подпись стоит убрать.

```bash
python3 tools/kie_images.py --balance          # остаток кредитов
python3 tools/kie_images.py --dry-run          # показать итоговые промты, ничего не вызывать
python3 tools/kie_images.py                    # сгенерировать всё из data/service_photos.json, чего ещё нет
python3 tools/kie_images.py --only pokraska --force   # перегенерировать одно фото
python3 build.py                               # страница подхватит фото, если файл существует
```

- Новая страница: добавить элемент в `data/service_photos.json` (`page`, `slug`, `alt`, `scene`). Общий фотостиль
  (объектив, свет, запрет надписей и логотипов) дописывает скрипт из константы `STYLE`.
- Модель по умолчанию `gpt-image-2-5-sunburst-text-to-image`, 3:2, 2K. Фактическая цена на 2026-09-21:
  10 кредитов за фото (1 USD = 200 кредитов, то есть около 0,05 USD). `--model flare` быстрее.
- Номера задач хранятся в `tools/.kie_tasks.json`: прерванный запуск продолжает ждать и докачивать результат,
  а не платит второй раз. Файлы результата лежат на медленном хосте, поэтому скачивание идёт с докачкой.

## Схема услуг: как устроена и почему не тормозит

Прежняя «лупа» с увеличением заставляла браузер перерисовывать стекло на каждом кадре (`left/top`, `background-position`,
`mix-blend-mode`, анимируемый `filter` на всей машине) и пересчитывать стили 22 пульсирующих точек. 21.09.2026 в отдельной
лаборатории сравнили три замены и взяли вариант «прицел и прожектор» (архив лаборатории с вариантами A и B:
`_plans/lens-lab-2026-09-21.tar.gz`, папка не в репозитории). Что теперь в `src/assets/js/car.js` и `car.css`:

- Прицел (`.reticle`) и тёмная вуаль с мягким отверстием (`.spot` + `<canvas>` 512 px, растянутый CSS) создаются скриптом,
  двигаются только через `transform`, каждый на своём слое. Никаких копий картинки машины.
- Положение сглаживает один цикл `requestAnimationFrame`, который останавливается, когда всё замерло. Обработчики указателя
  только запоминают координаты. Геометрия (размеры сцены, положение пунктов списка) читается одним пакетом при появлении
  секции и при ресайзе, а не в каждом кадре.
- Во время сканирования не пульсируют неактивные точки (`.is-roaming`) и не приглушается список; бесконечные анимации
  секции ставятся на паузу вне экрана (`.is-paused`), бегущая строка и подсказка прокрутки тоже (`.is-offscreen`, `core.js`).
- Убраны `backdrop-filter` у ридаута и `drop-shadow` у HUD-линии.

Настройки в начале `car.js`: `SNAP` (радиус прилипания), `TAU_ROAM` / `TAU_JUMP` (плавность), `VEIL` (плотность тени),
`TOUR_MS` (шаг авто-тура). Размер прицела — `.reticle { width }` в `car.css`.

Замер 2026-09-22 (Chromium на видеокарте Apple M2, процессор замедлен в 4 раза, медиана трёх прогонов, 4 с ведения по машине):
процессор 2 800 мс → 1 536 мс, видеокарта 326 мс → 196 мс; при переходах между услугами видеокарта 346 мс → 126 мс.

## Тексты страниц услуг и SEO

**Состояние (23.09.2026): подробные тексты есть у всех 99 страниц услуг** — около 709 тыс. знаков, в среднем 7 200 на
страницу, 555 вопросов с ответами (разметка FAQPage). У каждой страницы свой главный запрос из Wordstat по Нижнему Новгороду
(`seo/assignments.json`: 98 утверждены, «Установка дополнительного оборудования» ждёт ответа владельца, что именно ставят).
72 страницы переименованы по спросу — таблица для владельца в `seo/renames.md`. Вопросы владельцу, ответы на которые
позволят дописать сроки и подтверждённые работы (о ценах не спрашиваем: новых цен на сайте не будет), — в двух версиях:

Подробный текст страницы услуги лежит в `data/content/<slug>.json` (формат — в докстринге `build/content.py`),
slug — путь без `/services/` и `.html`, `/` заменён на `__`. Страница без такого файла собирается по-старому.
Из файла берутся H1, короткое имя для меню (`nav_name` — оно же в списках, крошках и окне на схеме), `title`, описание,
вводный текст, цены с пояснением, признаки, состав работ, этапы, разделы, вопросы и ответы, связанные услуги, мастер.
Все страницы услуг получают разметку schema.org: `Service` (с организацией `AutoRepair` по `@id`, ценой «от», если есть прайс),
`BreadcrumbList`, а при наличии вопросов — `FAQPage` (`build/schema.py`).
На странице один призыв к действию: после прайса, а без прайса — пояснение «стоимость уточняйте» с кнопкой звонка.
Поле `"contact": "shop"` отдаёт страницу магазину: кнопка «Заказать звонок», пояснение про наличие детали и часы работы
магазина в боковой карточке (так сделана страница «Автозапчасти»).

Заголовки вкладок, описания и при необходимости H1 страниц, которые не относятся к услугам (главная, список услуг,
магазин, каталоги, поиск, оплата, доставка, контакты и другие), лежат в `data/page_seo.json` и заменяют старые заголовки
с перечнем ключевых слов. У магазина, каталогов и поиска там же записан главный запрос: валидатор не даст закрепить его

## Телефоны: iPhone 16 Pro и 17 Pro Max

Сайт проверяется в движке Safari (WebKit) на профилях iPhone 16 Pro (402×874) и iPhone 17 Pro Max (440×956),
в портретной и альбомной ориентации, на всех 114 страницах: `tools/iphone_audit.cjs` (как запустить — в шапке файла).
Проверяется: нет горизонтальной прокрутки, цели нажатия не меньше 44 pt (метки на схеме — 36 pt, они стоят плотно),
поля ввода не меньше 16 px (иначе Safari увеличивает страницу при фокусе), текст не мельче 11 px, ошибок в консоли нет,
а также работа слайдеров, меню, окна звонка, лайтбокса, вопросов и вкладок пальцем.

Что для этого сделано:
- **hover только там, где есть мышь.** На iPhone нажатый элемент остаётся в `:hover` до следующего касания, поэтому
  стрелка слайдера оставалась зелёной. Сборка сама переносит каждый селектор с `:hover` в `@media (hover: hover)`
  (`build/css_tools.py`, тесты в `tests/`); на компьютере каскад прежний. В исходных CSS `:hover` пишется как обычно;
- **безопасные зоны** (`viewport-fit=cover`): боковой отступ не уже выреза в альбомной ориентации (`--gutter-safe`),
  нижняя панель «Позвонить / Заявка», меню, лайтбокс и уведомления учитывают полоску «домой»;
- **касания:** цели нажатия 44 pt на сенсорных экранах (`@media (pointer: coarse)`), подсветка касания в цвет бренда,
  у нажатой стрелки есть отклик; при открытом меню нижняя панель прячется, при открытом окне страница за ним не скроллится;
- **клавиатура:** поля с правильными `autocomplete`, `inputmode`, `autocapitalize`; окно звонка и шаги заявки
  на телефоне не открывают клавиатуру сами;
- **вёрстка:** длинные заголовки переносятся по слогам только на узких экранах, цены на телефоне идут построчно,
  пользовательское соглашение складывается в одну колонку, список направлений под текстом услуги свёрнут;
  номера телефона в текстах услуг — ссылки `tel:`;
- **вес:** шрифты — вариативные, по одному файлу на семейство и алфавит (было по копии на каждое начертание:
  697 КБ при первом открытии, стало 158 КБ); аватары отзывов ужаты до 168 px (были 1080 px, ~1 МБ на страницу),
  фото команды — до 640 px; `site.css` и `site.js` подключаются с хешем содержимого.


## Чего компания не делает

Тонировка и установка сигнализаций: услуги не оказываются (уточнено у владельца 2026-09-21). Страниц, пунктов схемы
и упоминаний в текстах быть не должно. Из должностей двух сотрудников в `data/site.json` слово «тонировка» убрано.

## Бэкенд: что подключить после выкладки

Фронтенд отправляет формы на те же адреса, что и текущий сайт:

| Действие | Запрос |
|----------|--------|
| Заявка (3 шага) | `POST /call/request` (поля `request_part[...]`) |
| Заказать звонок | `POST /call` (`contact_name`, `contact_phone`, `car`, `vin_code`, `message`) |
| Модели по марке | `POST /findcar/requestmodels/id/<brand_id>` → `{data:[{id,name,year_start,year_end}]}` |
| Модификации | `POST /findcar/requestsizes/` (`id`, `year`) → `{data:[{id,name}]}` |
| Вход | `POST /login/popup`; восстановление: `/email/lostpass`, `/sms/lostpass` |
| Регистрация | `POST /registration` (`RegistrationForm[...]`) |

Если бэкенд недоступен (например, на статическом хостинге), формы показывают понятную ошибку
с телефоном, а выбор автомобиля автоматически переключается на ручной ввод.
Корзина (`#cart-link`) ведёт на раздел автозапчастей — подключите к реальной корзине магазина.
Ссылки каталогов `/cats/zapchasti_na_*.html` и поиск `/search/` обслуживаются существующим бэкендом.
Страницу `404.html` нужно назначить в настройках хостинга/nginx (`error_page 404 /404.html`).

## Деплой

- **GitHub Pages (превью для заказчика):** <https://scorpochabro-solo.github.io/garage_team/>.
  Репозиторий `scorpochabro-solo/garage_team`, Pages читает папку `docs/` ветки `main`.
  Пересобрать и выложить:

  ```bash
  python3 build.py --base /garage_team --out docs && git add -A && git commit -m "build: pages" && git push
  ```

- **Продакшен на своём домене (garage.team):** `python3 build.py` без флагов → `dist/`, залить содержимое в корень хостинга.
  `--base` нужен только когда сайт живёт в подпапке.

## Технологии

Семантический HTML5, современный CSS (custom properties, grid, clamp, `dialog`, scroll-snap),
ванильный JS без зависимостей, self-hosted вариативные шрифты (Unbounded, Manrope, JetBrains Mono), WebP.
Учитываются `prefers-reduced-motion`, клавиатурная навигация, ARIA-атрибуты, контраст AA.
